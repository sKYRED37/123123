# Развёртывание на bothost.ru

## Структура проекта

```
your-bot-repo/
├── bot.py               # точка входа (bothost по умолчанию ищет именно bot.py)
├── requirements.txt     # зависимости — ставятся автоматически через pip
├── .env.example         # шаблон переменных окружения
├── hots_rosters/        # сюда кладёте .txt файлы составов HotS
│   └── example_team.txt
└── README.md
```

## Шаги

1. Залейте эту папку в репозиторий на GitHub/GitLab.
2. На bothost.ru: «Создать бота» → «Git Deployment» → подключите репозиторий и ветку.
3. В разделе **Environment Variables** добавьте переменные из `.env.example`:
   - `BOT_TOKEN` — токен от @BotFather (обязательно)
   - `OWNER_ID` — ваш Telegram ID (обязательно, иначе не будут работать команды владельца)
   - `ANTHROPIC_API_KEY` — если используется
   - `HOTS_ROSTERS_DIR` — можно не трогать, по умолчанию `hots_rosters`
4. Нажмите «Deploy». bothost сам соберёт Docker-образ по `requirements.txt` и запустит `bot.py`.
5. После деплоя напишите боту `/start` — если всё ок, он ответит списком команд.

База данных — файл SQLite `esports_league.db`, создаётся автоматически рядом с `bot.py`
при первом запуске. Проверьте в настройках bothost, что диск/volume для контейнера
персистентный, иначе после каждого редеплоя данные (команды, игроки, статистика) обнулятся.

## Составы HotS (Heroes of the Storm)

Отдельная от CS-системы штука: команды регистрируются не через `/create_team`,
а просто файлами в папке `hots_rosters/`.

**Как это работает:**

1. Создаёте в папке `hots_rosters/` файл, например `liquid.txt`.
2. Первая строка файла — название команды, дальше — игроки, по одному на строке:

   ```
   Team Liquid
   Nazeric - Танк
   Glaurung - Assassin
   Snitch - Support
   Fan - Healer
   Bakery - Соло-лейн
   ```

   Роль после `-` можно не указывать — тогда игроку присвоится роль «Игрок».
   Строки, начинающиеся с `#`, игнорируются (можно оставлять комментарии).
3. Составы подхватываются автоматически при каждом запуске бота, а также
   вручную командой `/hots_reload` (модераторам/админам) — без перезапуска бота.
4. Если отредактировать файл существующей команды и снова вызвать `/hots_reload`,
   старый состав этой команды полностью заменится новым.

**Команды в боте:**

- `/hots` — список всех загруженных HotS-команд
- `/hots_team [название]` — состав конкретной команды
- `/hots_reload` — пересканировать папку и обновить составы (только модераторы/админы)

Так как bothost пересобирает контейнер из репозитория при пуше, самый надёжный способ
добавлять составы — коммитить файлы в `hots_rosters/` в репозиторий и пушить;
bothost задеплоит их вместе с кодом, и они подхватятся при старте бота.
Если на хостинге доступна файловая панель/консоль контейнера — можно класть файлы
и через неё, а затем просто вызвать `/hots_reload`, не дожидаясь редеплоя.
